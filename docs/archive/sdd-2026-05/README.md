# SDD: 主催者によるイベント自己管理機能（サーバー）

GUI 上で団体（主催者）がイベントを作成・編集し、参加者用 URL と運営用 URL が自動発行される機能のサーバー側仕様書。

## 背景

現状はイベント追加が手動 SQL（`events` テーブルへの INSERT）に依存しており、運用上「イベントを増やすたびに人手が必要」という制約があった（アプリ自体の再デプロイは本来不要だが、DB 操作のために開発者の関与が必須だった）。本機能はこれを GUI 化し、主催者が自律的にイベントを発行できるようにする。

## 設計の核心

**既存の `users(event_id)` + JWT(event_id) によるマルチテナント構造は一切変更しない。** その上に「主催者(Organizer)」という**イベント横断のアカウント種別**を新設する。

- 既存の運営・参加者は従来どおり event 単位（`event_id` を持つ JWT）
- 主催者は `event_id` を持たない別系統の JWT で動作 → 「イベントが無いと管理者ログインできない」鶏卵問題を解消
- 主催者がイベントを作成すると、そのイベントの**初期管理者（`role='manager'`）を自動発行**する。追加スタッフは作成後にロール付き（`manager`/`viewer`）で招待する（[04-auth.md](./04-auth.md) 4.4）
- 運営ロールを `manager`（編集可）/`viewer`（閲覧のみ）に分割。既存 `/admin/*` ルートは **preHandler の差し替え＋監査ログ記録の追加**で対応し、画面・ロジック本体は流用する
- 操作証跡を `audit_logs` に記録し、「誰が・いつ・何をしたか」をさかのぼれる（[02-data-model.md](./02-data-model.md) 2.4）
- 主催者登録の認証方式は**環境変数で切り替え可能**。今回は簡単な「招待制（登録キー）」を実装し、将来「自由登録」へコード変更なしで移行できる（[04-auth.md](./04-auth.md) 4.6）

## ユビキタス言語の追加提案

`docs/ubiquitous-language.md` に以下の追加を提案する（実装着手前に確定）。

| 用語 | 定義 |
|------|------|
| 主催者 / Organizer | イベントを横断して作成・編集できるプラットフォームレベルのアカウント。`event_id` を持たない |
| 主催者ポータル / Organizer Portal | 主催者がイベントを管理する画面群 |
| 初期管理者自動発行 | イベント作成時に、そのイベント用の `role='manager'` ユーザーを同時に作成すること |
| 運営管理者 / Manager | イベント単位の運営ロール。ブース等の作成・編集・削除が可能 |
| 運営閲覧者 / Viewer | イベント単位の運営ロール。閲覧のみ可能 |
| スタッフ招待 | 主催者がイベントに運営スタッフ（manager/viewer）を email・ロール指定で追加すること |
| 監査ログ / Audit Log | 誰が・いつ・何をしたかの操作証跡（`audit_logs`） |
| 参加者 URL / 運営 URL | イベント作成時に発行される、参加者登録画面・運営ログイン画面への入口リンク |

## 非対象（このフェーズでやらないこと）

- 主催者間の権限委譲・共同編集（複数主催者で 1 イベントを共有）
- 課金・プラン管理
- イベントの公開/非公開ステート遷移（必要なら別フェーズ）
- 既存運営画面のビジネスロジック変更（ブース等の処理本体は流用。今回触るのは権限境界＝preHandler 差し替えと監査ログ記録の追加のみ）
- URL のメール送信（今回はコピペ共有のみ。将来対応）
