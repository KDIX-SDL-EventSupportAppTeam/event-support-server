# SDD: 主催者ポータル Phase 2・運営画面改善（サーバー）

主催者ポータルの「作成だけ」から「一覧・詳細・スタッフ管理」への拡張と、
運営画面改善に必要なサーバー側 API を定義する。
フロントエンド仕様は `event-support-frontend/.sdd/2026-07-05-organizer-portal-phase2/` を参照。

## 背景

Phase 1（`.sdd/` 直下の SDD）でイベント作成・URL 発行・スタッフ招待は完成したが、

- ログイン後の着地先が作成フォームで、**作成済みイベントを見る手段がない**
  （`GET /organizer/events` は空配列を返すスタブのまま）
- スタッフ招待の UI 入口が作成直後の 1 回だけで、**後からスタッフを確認・変更・削除できない**
  （そもそもスタッフ一覧を返す API が存在しない）
- 発行 URL を後から再表示できない

という UX 上の欠落が残っている。本 SDD はこれを解消する。

## 制約（確定事項）

- **DB スキーマ変更はしない。** イベントのタグ・属性カラム追加は見送り。
  「開催ステータス（準備中 / 開催中 / 終了）」は `date_start` / `date_end` と現在時刻からの
  **導出値**とし、DB には持たない（判定はフロントエンドで行う。サーバーは日時を返すだけ）
- 既存 API 契約（Phase 1 のレスポンス形式）は変更しない。追加のみ

## ドキュメント構成

| ファイル | 内容 |
|----------|------|
| [01-api.md](./01-api.md) | 新規・変更エンドポイント定義（イベント一覧/詳細・スタッフ管理・公開イベント情報）、権限ガード、監査ログ action |

## 実装フェーズ（フロント側と同期）

| フェーズ | サーバー側の作業 |
|---------|-----------------|
| P2-1 一覧・詳細 | `GET /organizer/events` 実装（スタブ置換）、`GET /organizer/events/:event_id` 新設 |
| P2-2 スタッフ管理 | staff の GET / PATCH / DELETE 新設、最後の manager ガード、監査ログ action 追加 |
| P2-3 公開イベント情報 | `GET /events/:event_id/public` 新設（JoinPage・AdminLoginPage のイベント名表示用） |

## 前提・関連

- 権限分離・監査ログ基盤は PR #39 で実装済み（`requireStaff` / `requireManager` /
  `insertAuditLog` / `GET /admin/events/:event_id/audit-logs`）。本 SDD はこれを流用する
- オーガナイザーの所有権チェックは `routes/v1/organizer/staff.ts` の
  「`SELECT id FROM events WHERE id = ? AND organizer_id = ?`」パターンを共通ヘルパー化して流用する
- `.sdd/2026-07-02-code-review/` の是正（特に B-3: affectedRows による誤 404）と競合しないよう、
  本 SDD の新規エンドポイントでは最初から「存在確認は SELECT で行う」方式を採用する

## ユビキタス言語の追加提案

| 用語 | 定義 |
|------|------|
| 開催ステータス | イベントの時間的状態。`date_start`/`date_end` と現在時刻から導出する（準備中 / 開催中 / 終了）。DB には保存しない |
| スタッフ管理 | 主催者がイベントのスタッフを一覧・ロール変更・削除すること（招待は Phase 1 で定義済み） |

## 非対象（このフェーズでやらないこと）

- events テーブルへのカラム追加（タグ・説明・公開ステート等）
- イベント削除・アーカイブ（既存 SDD 3.8 に記載はあるが本フェーズから除外。必要になったら別途）
- スタッフ招待のメール送信・招待リンク化（現行のパスワード直接指定方式を維持）
- スタッフ本人によるパスワード変更 API（別フェーズ。フロント側 SDD の「将来」参照）
