## SV-R1. 同一ロールへの PATCH が no-op でも監査ログに記録される 【低】

**現象**
`PATCH /organizer/events/:event_id/staff/:user_id` は、変更後ロールが現在と同じでも
UPDATE を実行し `staff.role_change` を記録する。フロントは同値変更を弾いているが、
API 直叩きでは `from_role === to_role` の無意味なログが積まれ、操作履歴の信頼性を下げる。

**修正仕様**
- 正規化後のロール（`admin` は `manager` とみなす）が `toRole` と同じ場合、
  UPDATE・監査ログをスキップして現在のスタッフ情報を 200 で返す（冪等）
- 例外: 対象の生ロールが `'admin'` で `toRole === 'manager'` の場合は、
  旧ロール表記の正規化を目的として UPDATE を実行してよい（監査ログは記録しない）

**受け入れ条件**
- manager → manager の PATCH が 200 を返し、audit_logs に行が増えない
- manager → viewer → manager の一連では 2 行記録される
