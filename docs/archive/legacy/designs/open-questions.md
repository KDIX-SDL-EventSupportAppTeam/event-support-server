# レビュー・妥当性確認の観点

アーキテクチャ・API・DB・フロントをまたいで確認したい論点です。実装前の設計レビュー用チェックリストとして使います。

**関連:** [設計インデックス](./README.md) · [システム・サーバー設計](./system-server.md) · [DB設計](./database.md) · [API設計](./api.md) · [フロントエンド](./frontend.md)

---

1. **同時接続200〜500に対してFastify + MySQL（InnoDB）の構成は妥当か**
2. **WebSocket（socket.io）とREST APIを1サーバーに同居させる構成に問題はないか**
3. **推薦エンジンをPython + FastAPIで分離する構成のレイテンシは許容範囲か**
4. **Service Workerによるオフラインキュー設計に見落としているリスクはないか**
5. **Google Apps Script → バックエンドAPIのWebhook構成はセキュリティ上問題ないか**
6. **イベント固有アンケート回答を MySQL の `JSON` カラムで持つ設計は分析クエリの観点から問題ないか**（必要に応じ生成列・正規化の切り出し）
