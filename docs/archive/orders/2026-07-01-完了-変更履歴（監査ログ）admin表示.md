# 作業指示: 変更履歴（監査ログ）の admin 表示 — サーバー側

- **日付:** 2026-07-01
- **状態:** 完了
- **関連:** frontend `docs/orders/2026-07-01-完了-変更履歴（監査ログ）admin表示.md`

## 背景

運営画面（admin）で「誰がどんな操作をしたか」を確認したいという要望。
監査ログの記録（`audit_logs` テーブル・`insertAuditLog`）と取得 API は
すでに実装済みだが、レスポンスに操作者の**メールアドレスが含まれていなかった**。
フロントで「メアド・表示名・操作内容」を並べて表示するために不足していた。

## 目的

`GET /admin/events/:event_id/audit-logs` のレスポンスに `actor_email` を追加し、
フロントが表示名とメアドの両方を出せるようにする。API 契約は後方互換（追加のみ）。

## 作業内容

- [x] `src/routes/v1/admin/audit-logs.ts`
  - `AuditLogRow` に `actor_email: string | null` を追加
  - SELECT に `u.email AS actor_email` を追加（既存の `users` LEFT JOIN を利用）
  - レスポンス map に `actor_email: r.actor_email ?? null` を追加

## 受け入れ条件

- レスポンスの各 `audit_logs[]` に `actor_email` が含まれる（未マッチ時は `null`）。
- 既存フィールド（`actor_display_name` 等）とページネーションの形は不変。
- 権限は従来どおり `requireStaff`（manager / viewer 両方が閲覧可）。

## 実装メモ

- 記録される `action` 一覧（`target.verb` 形式）:
  `staff.invite` / `booth.{create,update,delete}` /
  `category.{create,update,delete}` / `survey_question.{create,update,delete}`。
- `event_id` は URL とJWT の一致を `requireEventMatchesJwt` で担保済み。
- ローカルで `audit_logs` テーブルが無い場合は migration 再実行が必要
  （`docker compose down -v` からのフルセットアップ。memory: event-support-local-dev-setup 参照）。

## 補足: 運営者ロールの切り替えと admin ログイン 401 について

- ロール（manager / viewer）はイベント作成画面の「スタッフを追加する」フォームで選択し、
  `POST /organizer/events/:event_id/staff` に `role` を渡して作成する。
  イベント作成本体の `initial_manager` は常に `manager` 固定。
- admin ログインは `event_id + email + password` の 3 点照合。追加した運営者は
  **その新規イベントの event_id** に紐づくため、フロントのログイン先 event_id が
  seed イベントのままだと一致せず **401**。フロント側で `VITE_DEV_EVENT_ID` を
  対象イベントに合わせて Vite を再起動すれば解消する（コード変更不要）。
