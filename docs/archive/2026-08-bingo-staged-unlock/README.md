# SDD: ビンゴカード段階解放方式（サーバー / DB）

第4回プロトフェス（2026-10-16 金）向け、ビンゴカードを「中央4マス先行 → 外側12マス後出し解放」に作り替えるためのサーバー・DB 仕様書。意味単位でディレクトリを分割している。

**この仕様書は実装の正本である。** 実装セッションはまずこの README を読み、次に `01-concept` を読んでから該当ディレクトリに入ること。

## 一言でいうと何をするのか

参加者は最初、**中央2x2の4マスだけ**を持つ。うち1マスはサインアップ時に「参加ボーナス」として達成済みで配られ、残り3マスは**参加者が自由に選んで訪問したブースが後出しで埋まる**。中央4マスが揃った瞬間に外側12マスが解放され、そこに蓄積データを使った推薦ブースが配置される。

去年の最大の欠陥は「訪問6件に対して達成3マス」＝**訪問の半分がカードに載っていなかった**こと。後出し方式はこれを構造的に解消する。同時に、ゼロデータで16マスを決める無理筋を「3件の訪問と評価が溜まるまで待つ」に置き換える。

## 絶対に破ってはいけない制約

1. **16マス（4x4）固定。** 運営の意向。マス数の変更は検討対象外
2. **推薦を「推薦欄」のような外部UIに切り出さない。** ビンゴゲーム自体に同化させる
3. **成功の定義は踏破率ではない。** 「参加者が自分では選ばなかったブースを訪問し、それが新しい興味になること」。人気ブースを全員に薦めて踏破率が上がるのは**失敗**である。フォールバックを人気順で書いてはならない（[05](05-recommender/fallback.md)）
4. **中央4マス完成でガチャコインを配らない。** 中央2x2 はラインを構成しないため、そもそも成立しない。特別処理を書かないこと
5. **`state='LOCKED'` のマスの `booth_id` を API で返さない。** 解放前に中身が漏れる
