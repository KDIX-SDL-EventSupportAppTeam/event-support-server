# 背景 — なぜ動的段階解放にするのか

実装は不要。判断の根拠として読む。数値は第3回プロトフェス（2025-10-10 金）の実データ分析
（`event-support-analytics`）による。母集団: 登録302名 / チェックイン実績252名 /
総チェックイン2,114件 / 40ブース。今年は金曜開催のため**金曜を代表日**とする。

## 1. 去年のビンゴは機能していなかった

- 訪問ブース数 中央値 **6.0** / 平均 7.12（全40ブース中）
- 達成マス数 中央値 **3 / 16**、4ライン完走率 14.9%
- → **訪問の半分がビンゴに反映されていなかった。** カードに載っていないブースへ行っていたため

これが最大の設計欠陥である。カードを後から埋める方式にすると、
解放前は**参加者の全訪問がカードに反映される**。

## 2. 参加者は「時間切れ」で帰るのではない

- 滞在時間 中央値 64.5分 / 平均 84.4分。30分未満が **37.0%**、3時間以上が 11.5%（二峰性）
- 回帰式: 訪問数 ≒ 5.78 + 1.66 × 滞在時間(h)。**傾きが小さい**
- → 「回るべきものを回り終えた」から帰っている。伸びしろは時間ではなく**動機**の側にある

## 3. コールドスタートは「初回ログイン時点の蓄積量」の問題

去年の推薦は初回ログイン時の一発勝負だった。効くのは各参加者がカードを受け取った瞬間の蓄積量である。

| 初回ログイン | 新規人数 | その時点の累計チェックイン |
|---|---|---|
| 11:00 | 15 | 約20 |
| 12:00 | 15 | 約90 |
| 13:00 | 25 | 約154 |
| 13:30 | 43 | 約380 |
| 14:00 | 31 | 約639 |
| 15:00 | 23 | 約1,146 |

- 累計200件未満でカードが生成された参加者 = 70名（**37%**）
- 去年のフォールバック解除は 11:34（累計約60件 = 1ブース1.5人）。統計的にノイズであり、
  解除直後の推薦は事実上**ブース人気度ランキング**に退化していたと推定される。
  その上位は飲食ブースと制作チーム自身のブースであり、成功の定義に寄与していない

**動的解放は、推薦の実行タイミングを来場から15〜30分後ろへずらす。**
11時に来た参加者でも、3回目の解放は11:30前後になる。去年より必ず良い条件で推薦できる。

## 4. 1件目の訪問は選好情報として使えない

金曜の初回訪問先（n=192）は 1位 飲食 13.5% / 2位 制作チーム自身 10.9% / 上位3件で 32.3%。
「会場に着いたら飲み物を買う」という生理であり、技術的興味を反映しない。

→ **1回目の解放（訪問2件目）に強い推薦を期待してはいけない。**
1回目はコストを下げるための解放であり、精度はフェーズ設計で受け止める（[05-recommender/phases.md](../05-recommender/phases.md)）。

## 5. 時間帯の集中

13:30–15:30 の2時間に全チェックインの **72.6%** が集中する
（同時滞在ピーク 89名 / チェックインピーク 279件/30分 = 約9.3件/分）。
**解放処理もこの時間帯に集中する。** 性能とフォールバックの設計はここを前提にする。

## 6. 去年の推薦効果は交絡している

推薦マス踏破率 35.4% vs ランダムマス 27.0%（+8.4pt）。ただし推薦マスは**中央4マス固定配置**
だったため位置効果と交絡しており、アルゴリズムの効果とは断定できない。

**今年は位置効果が構造的に消える。** どの外周マスが開くかは中央マスの埋まる順序で決まり、
参加者ごとに異なるため、特定位置に推薦が偏らない。

## 7. データ量の見積もり

- 参加者150–200名 × 中央値6ブース = 総チェックイン **900〜1,200件**
- 評価の回収率は去年のアワード投票確定率 36.4% を基礎とすると **評価は約364件**
- DRSA の決定表に使える件数がこれで決まる。条件属性3個で 4×3×3 = 36通り、
  各パターン5件で **180件**が実用の下限
- → **評価回収率は UX の問題ではなく理論の成立条件**であり P0 である
  （[04-rating/rating-collection.md](../04-rating/rating-collection.md)）

## 8. 対策しないと決めたもの

| 項目 | 理由 |
|---|---|
| ブース間の訪問者数偏り | 最多128 / 最少25 = 5.12倍だが、1位が飲食・2位が制作チーム自身。この2つを除けば 3.24倍。訪問者0のブースは存在しない |
| 会場マップの座標データ化 | 上記の通り偏りが軽微 |
| チェックイン0件層（去年50名） | 去年の UX が原因。別のデザインアプローチで対応済み |
| 滞在時間の条件属性化 | ブース内容によって適正時間が異なりバイアスが乗る |
| ブースの所要時間（`duration_band`） | 同上の理由に加え、出展者が自己申告しづらい。今回は使わない |
| ブースの知識レベル（`knowledge_level`） | **評価しづらいデータであり扱わない**（2026-08-24 判断） |
| 過去イベントデータの再利用 | ブース構成が毎年変わる。**単一イベント完結を恒久的な設計制約とする** |
