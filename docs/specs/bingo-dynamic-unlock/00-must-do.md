# 絶対にやることリスト

**イベントは 2026-10-16 の1日だけ。当日のデータは二度と取り直せない。**
実装が終わってから思い出すのでは間に合わない項目を、先に固定しておく。

実装フェーズに入ったら、このファイルのチェックを埋めながら進める。
判定条件の詳細は [10-testing/acceptance-criteria.md](10-testing/acceptance-criteria.md)。

## テスト

- [ ] **段階解放ロジックを DB・通信に触れない純関数として切り出す。**
      あとから分離するのは非常に大変で、最初から分けるしかない
- [ ] 中央4マスの埋まり順を**総当たり（65通り）**でテストする
- [ ] 「起きてはいけないこと」を明示的にテストする（対応しないマスが開いていないこと）
- [ ] 解放の冪等性テスト（同一ペアで並行2回実行しても解放1回・ログ重複なし）
- [ ] 推薦サービスのタイムアウト／500 時にも解放が必ず成功することのテスト
- [ ] 自己修復が**解放3回ぶんすべて**で動くことのテスト
- [ ] **カード取得 API が見えないマスの中身を返さない**ことのテスト

## 実機・負荷

- [ ] **実機リハーサル**（研究室メンバー10名規模で、実際にスマホで QR を読んで一周する）
      → [10-testing/rehearsal-plan.md](10-testing/rehearsal-plan.md)
- [ ] **負荷試験**（想定の3倍 = 1分あたり30チェックイン）。
      解放1回の所要時間・SQL 往復回数・WebSocket 接続の安定性を測る
- [ ] 負荷試験の結果で「Cloud Run 1インスタンスで足りるか」を判断する。
      足りなければ socket.io のアダプタ方式導入（半日）を予備日程に確保する
- [ ] リハーサル用のイベントを**本番とは別に作る**（本番データを汚さない）

## フロント

- [ ] **解放演出の再生済みフラグを、解放イベントごとに独立して持つ。**
      1回きり前提の実装（localStorage の単一フラグ）を残さない
- [ ] 推薦欄 UI（`CheckInRecommendView`）を削除する
- [ ] 推薦理由文の表示 UI を削除する（**データの記録は残す**）
- [ ] ガチャ・アワード投票を「準備中」表示にし、旧 Flask 呼び出しコードを削除する

## データ

- [ ] `recommendations` テーブルを DROP し、**既存データも削除する**
- [ ] `recommendation_scores` に**候補全件**を記録する（推薦されなかったものが分母になる）
- [ ] `interest_match` と `attributes` を**推薦時点の値で凍結**して保存する
- [ ] `card_unlock_events` に `phase` / `decision_table_size` / `global_checkin_count` を必ず入れる
- [ ] カード外訪問を `cell_id = NULL` で必ず記録する（対照群になる）
- [ ] 事前アンケート回答が `user_survey_answers` に入り、分析側が決定表として読めること

## 当日の監視

- [ ] **評価回収率をリアルタイムで見られるようにする。**
      推薦手法が成立するかを左右する最重要指標
- [ ] 現在のフェーズと、次のしきい値までの残り件数を表示する
- [ ] 解放の到達人数（1回目 / 2回目 / 3回目）を表示する
- [ ] 直近30分のフォールバック率を表示する（推薦エンジンの障害検知）

## 運用

- [ ] マイグレーションは**事前アンケート側とまとめて1回**で実行する
- [ ] ロールバック手順を書く
- [ ] 当日トラブル時の運営向け手引きを書く
- [ ] 出展者・運営スタッフのアカウントを分析から除外できる状態にしておく
