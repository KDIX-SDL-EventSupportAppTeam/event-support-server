# ビンゴカード動的段階解放

第4回プロトフェス（2026-10-16 金）向け、ビンゴカードを
**「中央2マスが揃うたびに、その列の外周2マスを開放する」**方式に作り替えるための仕様書。

**この仕様書が実装の正本である。** 実装セッションはまず本 README を読み、
次に [01-concept](01-concept/) を読んでから該当ディレクトリへ入ること。

## 一言でいうと何をするのか

参加者は最初、**中央の4マスだけ**を持つ。うち1マス（position 5）には、
事前アンケートから推測した推薦ブースが**中身の見えた未訪問の状態**で置かれている。
残り3マスは空で、**参加者が自由に訪れたブースが後から埋まる。**

中央マスが2つ揃うと、その2マスが乗るビンゴ列の**外周2マス**が推薦ブースとともに開放される。
これが中央4マスすべて埋まるまで繰り返され、**解放は最大3回**（2マス→4マス→6マス）起きる。

去年の最大の欠陥は「訪問6件に対して達成3マス」＝**訪問の半分がカードに載っていなかった**こと。
後出し方式はこれを構造的に解消する。同時に、ゼロデータで16マスを決める無理筋を、
**データが溜まるにつれて推薦戦略を切り替える**設計に置き換える。

## 絶対に破ってはいけない制約

1. **16マス（4×4）固定。** 運営の意向。マス数の変更は検討対象外
2. **推薦を「推薦欄」のような外部 UI に切り出さない。** ビンゴゲーム自体に同化させる
3. **成功の定義は踏破率ではない。**「参加者が自分では選ばなかったブースを訪問し、
   それが新しい興味になること」。人気ブースを全員に薦めて踏破率が上がるのは**失敗**である。
   フォールバックを人気順で書いてはならない（[05](05-recommender/fallback.md)）
4. **中央4マス完成でコインを配らない。** 中央2×2 はラインを構成しないため、そもそも成立しない
5. **見えないマス（`is_revealed = 0`）の `booth_id` を API で返さない。** 解放前に中身が漏れる
6. **ビンゴはガチャコインに依存しない。** ビンゴが計算するのは成立ライン数まで
7. **確定していない仕様を実装しない。** [09-open-questions](09-open-questions/) は勝手に決めない
