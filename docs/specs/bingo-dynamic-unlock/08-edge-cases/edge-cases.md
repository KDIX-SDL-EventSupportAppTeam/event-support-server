# エッジケース

**実装時に必ず処理する。** 各項目はテストで固定する。

| # | 状況 | 扱い |
|---|---|---|
| E1 | 事前アンケート未回答でカードを要求する | カードは正常に生成する。position 5 は `booth_id = NULL`, `is_revealed = 0`。中央4マスすべてが自由枠になる |
| E2 | 事前推薦マスのブースへ実際に訪問する | **そのマスが達成になる。** 新しい中央マスを消費しない（[checkin.md](../03-card-lifecycle/checkin.md) 分岐1） |
| E3 | 関心分野に一致するブースが1つも無い | `pickPreSurveyBooth` が `null` を返す。E1 と同じ扱い |
| E4 | 中央2マス目と3マス目のチェックインがほぼ同時に届く | 各ペアの `card_unlock_events` INSERT が排他になる。解放は重複しない |
| E5 | 同じチェックインが2回送信される（通信リトライ・二度押し） | `check_ins` の `UNIQUE (user_id, booth_id)` で 409。INSERT 前 SELECT で判定する |
| E6 | ブースが当日中止になり、見えているマスに載っている | 運営が `reassign` API で差し替える（[admin-api.md](../06-api/admin-api.md)）。達成済みのマスは触らない |
| E7 | 有効ブース数が足りず、解放時に必要件数を埋められない | 埋められるだけ埋め、残りは `is_revealed = 1`, `booth_id = NULL`。`is_revealed = 0` のまま放置しない |
| E8 | 推薦サービスがタイムアウト / 500 を返す | フォールバックへ。**解放そのものは必ず成功させる**（[fallback.md](../05-recommender/fallback.md)） |
| E9 | 解放イベントは作られたが、マスの更新中に DB エラーが起きた | カード取得 API の自己修復で回復する。**3回ぶんすべてを点検する** |
| E10 | 推薦結果に、既にカードに載っているブースが含まれる | 呼び出し側で除去する。**推薦側を信用しない**。除去後の不足はフォールバックで補う |
| E11 | 推薦結果に、存在しない / `is_active = 0` のブースが含まれる | 捨てる。不足はフォールバックで補う |
| E12 | 運営スタッフ・出展者がテストでチェックインする | 訪問者数の集計から `users.role <> 'participant'` を除外する |
| E13 | 参加者が外周マスのブースへ訪問する | マスは達成になるが、**解放は起きない**（[unlock-pairs.md](../03-card-lifecycle/unlock-pairs.md)） |
| E14 | カードに載っていないブースへ訪問する | `cell_id = NULL` で記録する。ビンゴには寄与しないが**評価は同じように求める** |
| E15 | 中央4マスすべて達成したがラインが0本 | 正常。中央2×2 はラインを構成しない（[lines.md](../03-card-lifecycle/lines.md)） |
| E16 | 参加者が3回すべての解放を受ける前に帰る | そのまま。`card_unlock_events` の行数が到達段階を表す。**離脱の分析材料になる** |
| E17 | 同一ユーザーの `ensureCard` が同時に走る | `UNIQUE (event_id, user_id)` で1枚。重複は `ON DUPLICATE KEY UPDATE` で例外にせず、INSERT 後に**読み直して返す**（`ER_DUP_ENTRY` の catch に頼らない。ADR 0001） |
| E18 | カテゴリが当日編集され、推薦時と分析時で判定が変わる | `interest_match` / `attributes` を**推薦時点の値で凍結**しているので影響しない |
| E19 | 評価が1件も付いていない状態で解放が走る | `COVERAGE` フェーズで動く。例外を投げない |
| E20 | 解放通知の socket が届かない（スマホがバックグラウンド） | チェックインレスポンスの `unlocked_positions` が正の経路。カード取得でも `unlock_events` が取れる |
| E21 | 解放演出が繰り返し再生される / 1回目しか出ない | フロントの再生済みフラグを**解放イベントごとに独立**して持つ。1回きり前提の実装を残さない |
