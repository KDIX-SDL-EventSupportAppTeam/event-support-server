# 画面

**UI の正本は `event-support-frontend` 側。** ここには API との接点だけ書く。

## 復活させる3画面

既存の `LegacyPlaceholderPage` を外し、3段構成に戻す。
**スタッフの立会いは無く、操作はこの3画面で完結する**（G-10）。旧実装にあった
「スタッフと一緒に操作してください」の文言は使わない。

| 経路 | 画面 | やること |
|---|---|---|
| `/gachapon` | 注意事項 | 「一度使うと戻せない」の告知のみ。API を呼ばない |
| `/gachapon/use` | 使用確認 | GET で枚数を出し、確定で POST。**冪等キーはこの画面のマウント時に1個生成**し、リトライでも使い回す |
| `/gachapon/complete` | 使用済み | 消費した枚数目と時刻、残り枚数を出す。**参加者自身が確認するための画面** |

## 実装上の約束

- **「使用する」ボタンは押下直後に disabled にする。** サーバー側の防御はあるが、
  そもそも2回送らない
- 冪等キーは**ボタン押下ごとではなく1操作につき1個**。失敗して再試行するときは同じ値
- `409 NO_COINS_AVAILABLE` は「他の端末で使い切った可能性」を示すメッセージにし、GET で再取得する
- `403 GACHA_DISABLED` は「準備中」表示に落とす
- ホームのコインボタンは `available` を表示し、0 枚なら無効化する
- `ApiParticipantClient` のスタブ2本（`getAvailableGachaponCoins` / `postUseGachaponCoin`）は
  **削除**し、`features/gachapon/api/gachaClient.ts` に置き換える

## 立会いが無いぶん厚くすること（G-12）

取り消せない操作を、人間の目視確認なしで実行させる。UI 側の防御を明示的に決めておく。

- 確認は **`/gachapon/use` の1段のみ**。二重確認モーダルは重ねない（押し慣れて無意味になる）
- 「使用する」は**押下直後に disabled**。ラベルを「使用中…」に変える
- 使用ボタンは**破壊的操作の色**（`btn-danger`）で、「戻る」より視覚的に重くしない
- 完了画面に「**何枚目・何時何分・残り何枚**」を出す。誤って使ったかどうかを本人が判断できる
- 残り 0 枚のとき、`/gachapon/use` は使用ボタンを**表示しない**（disabled ではなく非表示）
- 完了画面から `/gachapon/use` へ**戻れない**（履歴を置換して遷移する）
