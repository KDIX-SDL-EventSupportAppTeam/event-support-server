## 3. ブース分析ウィンドウ

### 目的

全ブースを画面いっぱいに並べ、多角的なソート・フィルタで現状を俯瞰する。

### 表示コンポーネント

#### 3-1. ブースグリッド（メイン）

全ブースをカード形式でグリッド表示。画面幅に応じてカラム数を自動調整（CSS Grid）。

各ブースカードの表示項目：
- ブース名・手動コード
- カテゴリ（バッジ）
- タグ（バッジ）
- チェックイン数（数値 + 相対バー）
- 平均評価（★表示、null の場合「未評価」）
- 推薦採用率（このブースが推薦されて選ばれた割合）
- チェックイン方法比率（QR / 手動）
- ステータス: 「未訪問」「人気」「低評価注意」などのラベル（自動付与）

#### 3-2. ソート・フィルタ UI（ツールバー）

**ソート条件（単一選択）:**
- チェックイン数（多い順 / 少ない順）
- 平均評価（高い順 / 低い順）
- 推薦採用率（高い順 / 低い順）
- コード順（昇順 / 降順）
- 作成日時（新しい順 / 古い順）
- 未訪問優先（チェックイン0を先頭）

**フィルタ条件（複数選択可）:**
- カテゴリで絞り込み
- 未訪問のみ表示
- 評価あり / なし

#### 3-3. カテゴリ別サマリー

カテゴリごとの合計チェックイン数・平均評価を横棒グラフで表示。  
カテゴリ未設定のブースは「未分類」グループとして表示。

### 必要な新規 API エンドポイント

```
GET /api/v1/admin/events/:event_id/analytics/booths
```

**レスポンス:**
```typescript
{
  booths: {
    id: string
    name: string
    manual_code: string
    category: { id: string; name: string } | null
    tags: string[]
    checkin_count: number
    checkin_by_method: { qr: number; manual: number }
    avg_rating: number | null
    rating_distribution: { 1: number; 2: number; 3: number; 4: number; 5: number }
    recommendation_offered_count: number   // 推薦で提示された回数
    recommendation_selected_count: number  // 推薦で選ばれた回数
    recommendation_acceptance_rate: number | null  // selected / offered
  }[]
  category_summary: {
    category_id: string | null
    category_name: string
    total_checkins: number
    avg_rating: number | null
    booth_count: number
  }[]
}
```

**実装上の注意:**  
`recommendation_offered_count` は `recommendations.offered_booth_ids`（JSON）を全件取得後、
Node.js 側で `JSON.parse()` して集計する（さくら MySQL は JSON_TABLE 非対応）。

## 4. 参加者分析ウィンドウ

### 目的

参加者の属性・行動パターンを時系列・比較で把握し、運営介入の判断に使う。

### 表示コンポーネント

#### 4-1. 参加タイミンググラフ（メイン）

**グラフ種別**: 面グラフ（Area chart）または棒グラフ  
**X軸**: イベント開始からの経過時間（10分刻み）  
**Y軸**: その時間帯に「初回チェックイン」した参加者数（= イベントに実質的に参加したタイミング）  
**重ねて表示**: 累積参加者数ライン（二重軸）

#### 4-2. 直近30分の盛り上がり指標

- 直近30分のチェックイン数（全ブース合計）
- 直近10分のチェックイン数（より短期）
- 前30分との比較（増減率）→「盛り上がり中 ↑」「落ち着き中 ↓」を表示

#### 4-3. 参加者一覧テーブル（フィルタ・ソート付き）

**表示列:**
- 表示名・メール
- ロール（participant / admin）
- 登録日時
- 初回チェックイン時刻（= イベント参加タイミング）
- チェックイン数
- 訪問ブース名リスト

**フィルタ:**
- ロール（participant のみ / admin のみ / 全員）
- チェックイン済み / 未チェックイン
- 時間帯（登録時刻 or 初回チェックイン時刻で範囲指定）

#### 4-4. チェックイン数分布

何回チェックインした人が何人いるかのヒストグラム。  
例: 「0回: 5人」「1回: 3人」「2回: 2人」「3回: 1人」

#### 4-5. アンケート回答分布（survey_questions にデータがある場合のみ表示）

年齢層・職業・業種の分布を円グラフで表示。  
データなしの場合は「アンケートデータなし」のプレースホルダーを表示。

### 必要な新規 API エンドポイント

```
GET /api/v1/admin/events/:event_id/analytics/participants
```

**レスポンス:**
```typescript
{
  summary: {
    total: number            // role=participant のみカウント
    checked_in: number       // 1件以上チェックインした人数
    not_checked_in: number
    rolling_30min: number    // 直近30分のチェックイン数（全ブース合計）
    rolling_10min: number
    rolling_30min_prev: number  // 前30分（30〜60分前）のチェックイン数（比較用）
  }
  joining_timeline: {      // 初回チェックイン時刻の分布
    time_slot: string      // "10:00", "10:10", ...
    new_participants: number
    cumulative: number
  }[]
  checkin_distribution: {  // チェックイン数別の人数
    checkin_count: number
    num_users: number
  }[]
  participants: {
    id: string
    display_name: string
    email: string
    role: string
    registered_at: string
    first_checkin_at: string | null
    total_checkins: number
    visited_booths: { id: string; name: string }[]
  }[]
  survey_distribution: {   // アンケートデータがある場合のみ
    age_range: Record<string, number>
    occupation: Record<string, number>
    industry: Record<string, number>
  } | null
}
```

## 5. チェックイン分析ウィンドウ

### 目的

イベント全体のチェックイン流量を時系列で可視化し、混雑・閑散のパターンを掴む。

### 表示コンポーネント

#### 5-1. 累積チェックイン折れ線グラフ（メイン）

**X軸**: 時刻（10分刻み）  
**Y軸左**: 各時間帯の新規チェックイン数（棒グラフ）  
**Y軸右**: 累積チェックイン数（折れ線グラフ）  
→ 棒と折れ線の複合グラフ（Combo chart）

#### 5-2. ピーク時間帯表示

最もチェックインが多かった時間帯をハイライト表示。  
「ピーク: 14:30〜14:40（25件）」のように強調。

#### 5-3. チェックイン方法比率

QR スキャン vs 手動コード入力の比率をドーナツグラフで表示。

#### 5-4. ブース別チェックイン時刻ヒートマップ（任意実装）

X軸: 時刻（30分刻み）、Y軸: ブース名。  
セルの色の濃さでその時間帯のチェックイン数を表現。  
※実装難易度が高いため後回し可。

#### 5-5. リアルタイムフィード（WebSocket）

直近のチェックインを最大20件リスト表示。  
新しいチェックインが来ると先頭に追加（古いものは末尾から削除）。

### 必要な新規 API エンドポイント

```
GET /api/v1/admin/events/:event_id/analytics/checkins
```

**レスポンス:**
```typescript
{
  timeline: {
    time_slot: string      // "10:00", "10:10", ...
    count: number          // その時間帯の新規チェックイン数
    cumulative: number     // 累積チェックイン数
  }[]
  by_method: {
    qr: number
    manual: number
  }
  peak_slot: string | null  // 最大チェックイン時間帯
  peak_count: number
  total: number
  recent: {               // 直近20件（リアルタイムフィード初期値）
    id: string
    booth_name: string
    user_display_name: string
    method: string
    checked_in_at: string
  }[]
}
```

## 6. 推薦分析ウィンドウ

### 目的

推薦エンジンの動作状況と、ブース間の「行動パターン」を可視化して運営介入に活かす。

### 表示コンポーネント

#### 6-1. 推薦サマリー

| 指標 | 説明 |
|------|------|
| 総推薦回数 | 推薦が発行された回数 |
| 選択率 | 推薦を受けてブースを選んだ割合 |
| オープン推薦数 | まだ選択されていない推薦の数 |
| 使用アルゴリズム | mab / random 等 |

#### 6-2. ブース別推薦採用率（横棒グラフ）

各ブースについて：
- 提示回数（recommended として offered された回数）
- 選択回数
- 採用率 = 選択 / 提示（%）

「提示されているのに選ばれない」ブースは運営のフォローサイン。

#### 6-3. ブース遷移分析（行動パターン）

あるブースにチェックインした後、次にどのブースにチェックインしたかを集計。  

SQL:
```sql
SELECT 
  a.booth_id AS from_booth,
  b.booth_id AS to_booth,
  COUNT(*) AS transition_count
FROM check_ins a
JOIN check_ins b ON a.user_id = b.user_id 
  AND b.checked_in_at > a.checked_in_at
JOIN (
  SELECT user_id, booth_id, checked_in_at,
    LEAD(booth_id) OVER (PARTITION BY user_id ORDER BY checked_in_at) AS next_booth
  FROM check_ins WHERE event_id = ?
) next ON a.user_id = next.user_id AND a.booth_id = next.booth_id
WHERE a.event_id = ?
GROUP BY a.booth_id, b.booth_id
ORDER BY transition_count DESC
```

※データが少ない場合は「データ不足（参加者が増えると表示されます）」を表示。

#### 6-4. 推薦→チェックインコンバージョン

推薦でブースを選択した後、実際にそのブースへチェックインしたかを追跡。  
`recommendations.selected_booth_id` と `check_ins.booth_id` を突合。

| 指標 | 説明 |
|------|------|
| 推薦選択後チェックイン率 | 選択したブースへ実際にチェックした割合 |
| 平均チェックインまでの時間 | 推薦選択から実際のチェックインまでの分数 |

#### 6-5. アルゴリズム説明パネル

現在使用中のアルゴリズム（mab = マルチアームドバンディット）の動作原理を簡潔に説明するカード。  
将来的に複数アルゴリズムを比較できる欄として使う。

### 必要な新規 API エンドポイント

```
GET /api/v1/admin/events/:event_id/analytics/recommendations
```

**レスポンス:**
```typescript
{
  summary: {
    total_recommendations: number
    selected_count: number
    acceptance_rate: number   // selected / total
    open_count: number        // selected_booth_id が null の件数
    algorithm: string
  }
  by_booth: {
    booth_id: string
    booth_name: string
    offered_count: number
    selected_count: number
    acceptance_rate: number | null
  }[]
  transitions: {           // ブース遷移（データ少ない場合は空配列）
    from_booth_id: string
    from_booth_name: string
    to_booth_id: string
    to_booth_name: string
    count: number
  }[]
  conversion: {
    selected_then_checkedin: number  // 推薦選択→チェックインした件数
    selected_total: number
    conversion_rate: number | null
    avg_minutes_to_checkin: number | null
  }
}
```

**実装上の注意:**  
`offered_booth_ids` は JSON 文字列（MySQL の JSON カラム）のため、
全件 SELECT 後に Node.js 側で `JSON.parse(row.offered_booth_ids)` して集計する。

### 8-3. recommended_booth_ids の集計ロジック（アプリ層）

```typescript
// さくら MySQL は JSON_TABLE 非対応のため、全件取得後に Node.js で集計
const [rows] = await app.db.query(
  'SELECT offered_booth_ids, selected_booth_id FROM recommendations WHERE event_id = ?',
  [eventId]
)
const boothOfferedCount: Record<string, number> = {}
const boothSelectedCount: Record<string, number> = {}

for (const row of rows as { offered_booth_ids: string; selected_booth_id: string | null }[]) {
  const offered = JSON.parse(row.offered_booth_ids) as string[]
  for (const boothId of offered) {
    boothOfferedCount[boothId] = (boothOfferedCount[boothId] ?? 0) + 1
  }
  if (row.selected_booth_id) {
    boothSelectedCount[row.selected_booth_id] = (boothSelectedCount[row.selected_booth_id] ?? 0) + 1
  }
}
```

## 10. 拡張性の担保

- ウィンドウは `WINDOW_REGISTRY` 配列で管理し、後から追加するだけで反映される
- アナリティクス API は event_id ベースなので複数イベントに対応可
- グラフコンポーネントは `props` でデータを受け取る純粋コンポーネントにする（テスト容易）
- 推薦アルゴリズムが増えた場合も `algorithm` フィールドで区別可能
