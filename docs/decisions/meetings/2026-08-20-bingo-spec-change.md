# 2026-08-20 ビンゴカードの仕様変更（須藤先生との打ち合わせ）

- **参加者:** 須藤先生、三上
- **目的:** 去年のプロトフェス参加者データの分析結果共有、ビンゴゲーム・レコメンドシステムの
  課題整理、改善提案の議論、アプリのデモ
- **資料:** 三上作成のスライド「ビンゴゲーム改善提案会」（[assets/](assets/)）

## 1. 去年のデータ分析結果の共有

**提案**
2025年度プロトフェス参加者データ（Firestore）をダッシュボード化して分析。参加者（延べ）295、
実人数252、チェックイン数2,114、滞在時間中央値61分、訪問ブース数中央値6.0。
訪問ブース数の分布から「そもそも周遊率が悪い」「アプリを使ってもらえていない」の2点を提示。

**反論・意見**
アプリを使っていない2024年度以前のデータがないと、その結論は主張できない。
むしろ周遊率や使用率が上がった結果がこの数値である可能性もある。

**結論**
周遊率とアプリ利用率の向上を、今年度の改善提案の出発点として確定。

## 2. 「参加ありがとうマス」（事前進捗）の見直し

**提案**
中央4マスのうち1マスを「参加ありがとう」として最初から開放済みにする（事前進捗のサービス）。

**反論・意見**
須藤先生より不要との指摘。理由:

- 参考にした先行研究はゴールが明確な「山登り型」のタスクであり、本ビンゴのように
  ゴールが定まっていないオープンなタスクとは性質が異なる
- 16マス中1マスを最初から開けても「なぜここだけ開いているか」の説明が難しく、
  段階的目標としての意味も薄い。中央4マス→周辺という2段階構成だけで十分に段階化できている
- 4マス中1マスが最初から開いていても「3が4になっただけ」でハードルはほとんど下がらない
- 去年のデータとの比較の観点から、スタートが有利になりすぎて公平な比較ができなくなる

一方で「真っ白な状態からどこでも自由に行ってください」という完全な自由も、
最初の1歩を踏み出しにくい（心理学的コールドスタート）という点は妥当との指摘。

**結論**
「参加ありがとう」マスは廃止。代わりに、事前アンケートの興味カテゴリーから推測される1マスのみを、
最初からブース情報付きで開放しておく（ベタな推薦として提示）。残り3マスは完全に自由。

## 3. 段階的解放（動的ビンゴ）の詳細設計

**提案・確定した仕様**

- 4×4ビンゴマスを左上から1〜16番とカレンダー状に採番。中央の4マス（6, 7, 10, 11番）が核
- 6番: 事前アンケート結果から推測される推薦ブースとして、最初からブース情報を表示した状態でスタート
- 7, 10, 11番: 自由枠。参加者が実際に訪れたブースが訪問順に反映される
- 中央4マスが2マス埋まった時点で、そのマスに関連するビンゴ列に対してレコメンドが実行され、
  推薦ブースマスとして新たに開放される
- どのマスの組み合わせで埋まったかによって開放される列は変わる
- この流れを中央マスが全て埋まるまで繰り返す
- 外周マスが埋まっても隣接マスの開放は発生しない。開放が起きるのは中央マス起点のビンゴ列のみ
- 結果として、レコメンドの実行タイミングは1回ではなく複数回発生する

**反論・意見**

- 最初のビンゴ成立が去年より厳しくなる可能性について議論があったが、
  公平な比較・分析のしやすさを優先する方針で合意
- データベース設計への影響が大きいとの指摘:
  - ビンゴカードの各マスにロック/アンロック状態を持たせる必要がある
  - ロック状態のマスは中身を空のまま保持し、レコメンド実行後にアンロックして表示する
  - 現状はブース ID のみを保持している。参加者ごとの「そのブースに対する推薦度」を
    評価データと紐づけて保持する必要がある
- 「大掛かりな改造になりダイナミックな動作のためテストが難しくなる」との懸念が共有され、
  慎重な実装を求められた

**結論**
上記の段階的解放設計を正式な仕様として採用。データベース設計の見直しをエンジニア側タスクとする。

> **後日の補足（2026-08-24）:** 議事録に「7番・8番が先に埋まった場合は4番・13番」とあるが、
> 8番は外周マスであり中央ではない。4-7-10-13 は対角線であることから「7番・10番」の記録違いと
> 判断し、三上が確認して確定した。対応表は
> [specs/bingo-dynamic-unlock/03-card-lifecycle/unlock-pairs.md](../../specs/bingo-dynamic-unlock/03-card-lifecycle/unlock-pairs.md) にある。

## 4. 評価・検証方法

**提案**
段階的解放の効果検証を2軸で行う。(i) レコメンド自体の効果 = 推薦されたマスへの訪問割合を
去年と比較。(ii) 周遊率向上の効果 = 訪問ブース数の分布が右にシフトしたかどうか。

**反論・意見**

- 上記2軸は研究発表上、明確に分けて説明する必要がある。「段階的目標を立てたから」なのか
  「レコメンドの精度が上がったから」なのかを混同しないよう、周辺マスを隠す設計自体も
  レコメンドの見せ方の工夫の一部として位置づける
- ラフ集合アルゴリズム自体は変更しておらず、データの使い方・見せ方を変えている点を
  明確に説明できれば、研究としての妥当性に問題はない
- セレンディピティについて、当初は大学院進学後の研究テーマとして切り離す想定だったが、
  須藤先生からは「今回のラフ集合による推薦自体がすでにその要素を含んでいる」との指摘。
  アンケートで選ばなかったカテゴリーのブースが推薦された場合の訪問割合や満足度を分析すれば、
  今年度の範囲でも十分検証可能
- レコメンド理由の説明文をマスに表示する案は不採用。ユーザーが読まない可能性が高く、
  ビンゴゲームの形式自体が「次にどう行動すればよいか」を直感的に伝えられるため

**結論**
評価は「レコメンド効果」と「周遊率向上効果」の2軸で分析。セレンディピティの分析も今年度に含める。
マスへの推薦理由文は表示しない。

## 5. ブース評価・コメント機能

**提案**
チェックイン後の評価 UI を5段階評価＋「評価を送信」「コメント送信」の2ボタン構成にする。

**反論・意見**

- 5段階評価は中間（3）に回答が集中しやすい。中央値なしの4段階のほうが実験データとして分析しやすい
- 2ボタン構成は、評価とコメントのどちらをスキップしたか区別がつきにくく、UX としても冗長

**結論**
中央なしの星4段階評価を採用。星評価＋ブースへのコメント入力欄＋「完了」ボタン1つの構成に変更。

## ネクストアクション（三上）

- ビンゴマスのロック/アンロック状態を持つデータベース設計への改修
- 参加者ごとの「ブースに対する推薦度」を評価データと紐づけて保持する仕組みの実装
- 段階的解放ロジックの実装
- 評価 UI を中央なし星4段階＋コメント欄＋完了ボタン1つの構成に変更
- レコメンド効果／周遊率向上効果を分けて分析できるようログ・データ設計を見直す

その他の意見:

- ダイナミックな動的レコメンドへの変更は大掛かりな改修になるため、テストを含め慎重に進める必要がある
- HTML/ヘッダーのスキン分離（他イベント汎用化への対応）は急ぎではないが、別軸の検討事項として残す
